# Technical debt register

Deliberate shortcuts, recorded when taken rather than discovered later. Each
entry names the trade-off and what would trigger paying it off.

| # | Debt | Taken in | Why | Trigger to pay it off |
|---|---|---|---|---|
| 1 | PHPStan does not analyse `tests/Feature` and `tests/Unit` | Phase 1 | Pest binds `$this` in test closures at runtime; PHPStan sees `Pest\PendingCalls\TestCall` and flags every `$this->getJson()`. The fix, `pestphp/pest-plugin-phpstan`, needs Pest 5 → PHPUnit 13, and Laravel 13 pins PHPUnit 12. | Laravel 13 supports PHPUnit 13, or Pest backports the plugin. |
| 2 | Tests run against SQLite in-memory, production is MySQL 8.4 | Phase 1 | Keeps the suite at sub-second wall clock and hermetic on a laptop. | Phase 7 CI adds a MySQL job for the nightly run; anything touching partitions, `SKIP LOCKED` or `READ COMMITTED` semantics must be tested there, not on SQLite. |
| 3 | No production image target — the Dockerfile is dev-only (bind mount, `opcache.validate_timestamps=1`, source not baked in) | Phase 1 | Nothing deploys yet. | Phase 9, with the zero-downtime deploy pipeline. |
| 4 | Horizon dashboard has no authorization gate beyond the default `web` middleware | Phase 1 | Local only, not exposed. | Before anything is deployed anywhere reachable. `HorizonServiceProvider::gate()` is already scaffolded and empty. |
| 5 | `subscriptions` allows more than one row per (user, product) | Phase 1 | MySQL has no partial unique index, and "one *active* subscription per product" is a state-machine invariant, not a column constraint. | Phase 3, enforced in the subscription state machine plus a test that proves resubscribe-after-cancel still works. |
| 6 | `/health` is unauthenticated and unthrottled: it names infrastructure detail (eviction policies, drivers) and costs four dependency round-trips per hit | Phase 1 | Local only, and a probe must not depend on the auth or rate-limit infrastructure it exists to check — restricting it is a network-layer job, not a middleware one. | Before anything is deployed anywhere reachable: expose `/health` only to the load balancer / internal network, exactly like the Horizon gate in debt #4. |
| 7 | Ingest auth is one static bearer token shared by every producer | Phase 2 | The ingest hot path does auth + envelope validation only; per-product credentials, rotation and scoping belong with the API/auth work (Module 8). | Before any producer outside local dev: per-product keys with rotation, and the token comparison moves to a keyed lookup. |
| 8 | `events_archive` uniqueness is `(event_id, received_at)`, not `event_id` alone | Phase 2 | MySQL requires the partition column in every unique key. A duplicate could theoretically land twice with different `received_at` values — in practice only if a producer retries the same event_id after the dedup TTL (15 min) *and* the retries straddle different ingest seconds. | If reconciliation or projections ever observe a cross-second duplicate in the archive; the fix is a small unpartitioned `event_id → month` lookup table, at the cost of one extra insert per event. |
| 9 | The reaction map ships empty — the reactions consumer runs with nothing wired | Phase 2 | Domain reactions belong to billing, which does not exist until Phase 3. The machinery (markers, at-least-once dispatch, idempotency contract) is built and tested with a fake job. | Phase 3 wires the first real reactions (payment failure, trial expiry) into `config/events.php`. |
